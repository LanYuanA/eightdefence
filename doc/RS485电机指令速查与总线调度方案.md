# RS485 电机指令速查与总线调度方案

## 1. 设备映射

| 逻辑设备 | 型号 | 地址 | 说明书 |
|---|---|---|---|
| 机舱排烟风机 | 57 型 | `0x02` | `57一体伺服_RS485型_使用手册.pdf` |
| 消防水泵 | 42 型 | `0x0E` | `42一体伺服_RS485型_使用手册.pdf` |
| 舱底排水泵 | 42 型 | `0x0F` | `42一体伺服_RS485型_使用手册.pdf` |

公共参数：`/dev/ttyS9`、9600 baud、8N1。项目中的 `./test` 会自动追加 Modbus CRC，下面报文不包含 CRC。测试时总线上只能有一个程序，必须停止网关或其他串口工具。

## 2. 读取指令

### 状态字 6041h（U16）

```bash
./test /dev/ttyS9 020360410001 9600 500
./test /dev/ttyS9 0E0360410001 9600 500
./test /dev/ttyS9 0F0360410001 9600 500
```

返回示例：`02 03 02 00 27 ...`，其中数据 `0x0027`。有效回帧可作为在线心跳。

### 故障码 603Fh（U16）

```bash
./test /dev/ttyS9 0203603F0001 9600 500
./test /dev/ttyS9 0E03603F0001 9600 500
./test /dev/ttyS9 0F03603F0001 9600 500
```

`0x0000` 表示无故障；非零值进入异常保护。常见值：`0x2212` 硬件过流、`0x3211` 过压、`0x3221` 欠压、`0x8311` 过载、`0x4201` 过温、`0x7121` 堵转、`0x7310` 超速、`0x7320` 编码器故障。

### 运行状态 2009h（U16）

```bash
./test /dev/ttyS9 020320090001 9600 500
./test /dev/ttyS9 0E0320090001 9600 500
./test /dev/ttyS9 0F0320090001 9600 500
```

`0` 为静止，`1` 为运行。它只能辅助区分在线待机和在线运行。

### 实际转速 606Ch（I32）

读取两个 16 位寄存器：

```bash
./test /dev/ttyS9 0203606C0002 9600 500
./test /dev/ttyS9 0E03606C0002 9600 500
./test /dev/ttyS9 0F03606C0002 9600 500
```

返回的两个字按高字在前组合为有符号 32 位 RPM。说明书对读取数量存在示例差异，接入前必须以实机回帧确认字节序。当前后端已按 `606Ch + count=2` 读取；若设备拒绝该对象，应保留状态字在线，单独标记“转速反馈不可用”，不能把设备误报为离线。

## 3. 启动、停止和调速指令

启动流程按顺序写入。下列是 57 型 `0x02` 的指令，替换地址即可用于 42 型：

```bash
# 57 型，地址 0x02
./test /dev/ttyS9 020660400006 9600 500
./test /dev/ttyS9 020660400007 9600 500
./test /dev/ttyS9 02066040000F 9600 500
./test /dev/ttyS9 020660600003 9600 500
./test /dev/ttyS9 021060830002040000000A 9600 500
./test /dev/ttyS9 021060840002040000000A 9600 500
./test /dev/ttyS9 021060FF000204000000C8 9600 500

# 停止
./test /dev/ttyS9 020660400006 9600 500
```

42 型长电机地址 `0x0F`：

```bash
./test /dev/ttyS9 0F0660400006 9600 500
./test /dev/ttyS9 0F0660400007 9600 500
./test /dev/ttyS9 0F066040000F 9600 500
./test /dev/ttyS9 0F0660600003 9600 500
./test /dev/ttyS9 0F1060830002040000000A 9600 500
./test /dev/ttyS9 0F1060840002040000000A 9600 500
./test /dev/ttyS9 0F1060FF000204000000C8 9600 500
./test /dev/ttyS9 0F0660400006 9600 500
```

42 型长电机地址 `0x0E` 使用同样报文，将每帧首字节替换为 `0E`：

```text
0E0660400006
0E0660400007
0E066040000F
0E0660600003
0E1060830002040000000A
0E1060840002040000000A
0E1060FF000204000000C8
停止：0E0660400006
```

上面目标速度 `0x000000C8` 为 200 rpm，加减速度 `0x0000000A` 为 10。实际运行时由原子服务根据参数生成，不建议人工连续敲写入指令。

## 4. RS485 读取竞争根因

传感器轮询和电机遥测都进入同一个 `AsyncBus → CommandQueue → SerialBus`。传感器每 5 秒批量提交多个读请求；电机列表接口又在 Web 线程同步读取每台电机的 `606Ch` 和 `6041h`。当设备无响应或队列积压时，Web 线程会等待命令结果，表现为健康接口超时；直接运行 `./test` 时还会和网关同时读写，造成回帧串接。

## 5. 推荐解决方案

### 第一阶段：当前修复

- 所有串口事务继续经过唯一 `SerialBus`，禁止任何模块绕过队列直接读串口。
- `GET /marine/motors` 不应成为实时控制路径；电机遥测读取设置短超时，超时返回上一次缓存并标记字段级 `stale/feedbackUnavailable`。
- 在线判定只依据有效 `6041h` 回帧；`606Ch` 失败只影响 RPM 字段，不覆盖在线状态。
- Web API 线程不等待传感器轮询清空队列，接口必须在固定上限内返回。

### 第二阶段：调度隔离

将队列划分为三个优先级：

1. `URGENT`：停止、急停和安全命令，立即插队；
2. `CONTROL`：启动、目标速度、换向和参数更新；
3. `TELEMETRY`：传感器和电机周期性读取。

在 `TELEMETRY` 内设置每个设备的最小轮询间隔、队列上限和丢弃旧请求策略。电机状态心跳优先于低价值环境重复采样，过期的传感器请求直接丢弃，不让队列无限增长。

### 第三阶段：缓存和批量读取

- 由一个后台遥测线程周期性读取三个电机，将 `6041h、603Fh、2009h、606Ch` 写入线程安全缓存。
- API 只读缓存，返回 `updatedAt、ageMs、quality`，绝不在 HTTP 请求中发串口命令。
- 同一设备的连续寄存器尽量合并成一次读取；不支持合并时拆分为独立事务并保留字段状态。
- 控制命令完成后立即刷新对应设备缓存，避免页面等待下一轮轮询。

### 第四阶段：总线仲裁与可观测性

每个事务记录 `requestId、优先级、地址、寄存器、发送时间、回帧地址、CRC、耗时和失败原因`。增加队列深度、超时数、丢弃数和每地址成功率指标。发现同一串口被外部工具占用时，健康接口返回明确的总线占用错误。

## 6. 验收标准

- 网关运行时不再允许 `./test` 并行占用串口。
- `/api/v1/health` 在传感器无响应、队列堆积时仍在 1 秒内返回。
- `/api/v1/marine/motors` 在 1 秒内返回三个缓存状态；每个状态带新鲜度和 RPM 可用性。
- 连续读取 0x02、0x0E、0x0F 的状态字、故障码和运行状态，回帧地址必须与请求地址一致。
- 真实控制命令始终高于遥测读取；停止和急停不能被传感器轮询延迟。
- 实机测试前先停止网关，使用本文件的只读命令逐条验证；测试后再启动真实网关。
