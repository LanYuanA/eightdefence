## 1. 概述

本项目从 **单一应用单线程轮询** 架构升级为 **多线程+多应用** 架构。核心改动包括：

| 改动项 | 旧架构 | 新架构 |
|--------|--------|--------|
| 线程模型 | 单线程顺序轮询 | 多线程并行轮询，每个设备独立线程 |
| 应用管理 | 所有逻辑写在 main 中 | 多应用框架，每个应用独立模块 |
| 路由分发 | 硬编码 if-else | AppManager 统一路由分发 |
| 总线访问 | 直接读写串口 | 线程安全 SerialBus（互斥锁保护） |
| 扩展性 | 改 main.cpp | 继承 AppBase，注册即可 |

```
├─────────────────────────────────────────────────────┤

│                                                      │
│ ── 生命周期 ──                                       │
│ + init(): int                   [virtual]            │

│                                                      │

           △ 继承

    ┌──────┴──────┐

    │  (安防应用)  │
    └─────────────┘
```

#### 关键方法说明

| 方法 | 功能 | 调用时机 |
|------|------|----------|
| `init()` | 初始化应用，加载配置和资源 | `AppManager::initAll()` |
| `start()` | 启动业务线程，进入运行状态 | `AppManager::startAll()` |
| `stop()` | 停止业务线程，释放资源 | `AppManager::stopAll()` 或析构 |
| `handleApi()` | 处理 HTTP API 请求，返回响应 | WebServer 收到匹配请求时 |
| `matchRoute()` | 判断请求路径是否属于此应用 | 路由分发时 |
| `stripPrefix()` | 从完整路径中去除应用前缀 | 路由分发时 |
| `registerApi()` | 注册 API 路由处理器 | 子类构造函数中 |
| `getStaticDir()` | 返回前端静态文件目录 | WebServer 提供静态资源时 |
| `getIndexPage()` | 返回应用首页文件路径 | 浏览器直接访问应用时 |

#### 辅助结构体

```cpp
// HTTP 请求信息
struct HttpRequest {
    string method;       // GET, POST, PUT, DELETE
    string path;         // 请求路径 (已去除应用前缀)
    string fullPath;     // 完整路径
    string queryString;  // 查询字符串
    string body;         // 请求体 (POST/PUT)
    map<string, string> headers;
    
    string getParam(key);  // 从查询字符串中提取参数
};

// HTTP 响应信息
struct HttpResponse {
    int statusCode;
    string statusText;
    string contentType;
    string body;
    map<string, string> headers;
    
    static HttpResponse::json(jsonBody, code);   // 构造 JSON 响应
    static HttpResponse::html(htmlBody, code);   // 构造 HTML 响应
    static HttpResponse::error(code, message);   // 构造错误响应
};

// API 路由处理器类型
using ApiHandler = function<HttpResponse(const HttpRequest&)>;
```

### 3.2 AppManager - 应用管理器

**文件**: `application/app_manager.hpp`

单例模式实现，全局唯一，负责所有应用的注册、生命周期管理和路由分发。

#### 类图

```
┌──────────────────────────────────────────────────────┐
│              AppManager  (Singleton)                  │
├──────────────────────────────────────────────────────┤
│ - m_apps: vector<shared_ptr<AppBase>>   // 应用列表   │
│ - m_mutex: mutable mutex                // 线程安全锁 │
├──────────────────────────────────────────────────────┤
│ + static instance(): AppManager&        // 获取单例   │
│                                                      │
│ ── 应用管理 ──                                       │
│ + registerApp(app: shared_ptr<AppBase>): void        │
│ + findApp(name: string): shared_ptr<AppBase>         │
│ + getAllApps(): vector<shared_ptr<AppBase>>           │
│ + getAppCount(): size_t                              │
│                                                      │
│ ── 生命周期 ──                                       │
│ + initAll(): int          // 初始化所有应用           │
│ + startAll(): void        // 启动所有应用             │
│ + stopAll(): void         // 停止所有应用             │
│                                                      │
│ ── 路由分发 ──                                       │
│ + routeRequest(method, path, query, body)            │
│     → unique_ptr<HttpResponse>                       │
│                                                      │
│ - getAppsJson(): string    // 序列化应用列表          │
└──────────────────────────────────────────────────────┘
```

#### 路由分发优先级

```
收到 HTTP 请求
    │
    ├─ 路径 == "/api/apps" ?
    │   └─ YES → 返回应用列表 JSON
    │
    ├─ 遍历所有已注册应用:
    │   ├─ app->matchRoute(path) ?
    │   │   ├─ 子路径以 "/api/" 开头 ?
    │   │   │   └─ YES → app->handleApi(request) → 返回 API 响应
    │   │   │
    │   │   └─ 子路径不以 "/api/" 开头 ?
    │   │       ├─ 有 getIndexPage() ?
    │   │       │   └─ YES → 返回应用首页文件
    │   │       └─ 无首页 → 404 错误
    │   │
    │   └─ 不匹配 → 继续下一个应用
    │
    └─ 无应用匹配 → 返回 nullptr (由 WebServer 处理后续路由)
```

### 3.3 HttpRequest / HttpResponse - HTTP 请求/响应

**文件**: `application/app_base.hpp`

轻量级 HTTP 数据结构，用于应用与 WebServer 之间的数据传递。

#### HttpRequest

```cpp
struct HttpRequest {
    string method;       // HTTP 方法: "GET", "POST", "PUT", "DELETE"
    string path;         // 已去除应用前缀的路径
                        // 例: 完整路径 "/security/api/status" → path = "/api/status"
    string fullPath;     // 完整请求路径: "/security/api/status"
    string queryString;  // 查询字符串: "action=simulate&target=water"
    string body;         // 请求体 (POST/PUT 时有值)
    map<string, string> headers;  // HTTP 头

    // 便捷方法: 从查询字符串中提取参数
    string getParam("action")  → "simulate"
    string getParam("target")  → "water"
    string getParam("missing") → ""
};
```

#### HttpResponse

```cpp
struct HttpResponse {
    int statusCode;      // HTTP 状态码: 200, 404, 500 等
    string statusText;   // 状态文本: "OK", "Not Found"
    string contentType;  // 内容类型: "application/json; charset=utf-8"
    string body;         // 响应体内容
    map<string, string> headers;  // 额外响应头

    // 静态工厂方法 (快速构造常用响应)
    HttpResponse::json("{\"status\":\"ok\"}")          // 200 JSON
    HttpResponse::html("<html>...</html>")             // 200 HTML
    HttpResponse::error(404, "Not Found")              // 错误响应
    HttpResponse::json("{\"msg\":\"err\"}", 500)       // 500 JSON
};
```

## 4. 设计模式详解

### 4.1 单例模式 (Singleton Pattern)

**定义**: 确保一个类只有一个实例，并提供一个全局访问点。

#### 本项目中的实现

```cpp
// application/app_manager.hpp
class AppManager {
public:
    // ① 静态方法获取唯一实例 (Meyer's Singleton)
    static AppManager& instance() {
        static AppManager s_instance;  // 局部静态变量，线程安全(C++11+)
        return s_instance;
    }

private:
    // ② 私有构造函数 - 禁止外部创建
    AppManager() = default;
    ~AppManager() = default;

    // ③ 删除拷贝构造和赋值 - 禁止复制
    AppManager(const AppManager&) = delete;
    AppManager& operator=(const AppManager&) = delete;
};
```

#### 单例模式的三个关键要素

```
┌─────────────────────────────────────────────┐
│           单例模式三要素                      │
├─────────────────────────────────────────────┤
│                                             │
│  1. 唯一实例                                 │
│     static AppManager s_instance            │
│     → 全局只有一份，所有人共享同一对象        │
│                                             │
│  2. 私有构造函数                             │
│     AppManager() = default;                 │
│     → 外部无法 new AppManager()             │
│                                             │
│  3. 禁止拷贝                                 │
│     AppManager(const&) = delete;            │
│     → 外部无法复制出第二个实例               │
│                                             │
└─────────────────────────────────────────────┘
```

#### 为什么用单例模式？

```
场景: 系统中只有 1 个应用管理器，但多个地方都需要访问它:
  - main.cpp:      注册应用
  - web_server.cpp: 路由分发
  - 其他模块:       查询应用状态

如果不用单例:
  AppManager mgr1;   // main.cpp 创建
  AppManager mgr2;   // web_server.cpp 创建
  → mgr1 和 mgr2 是不同对象，注册的应用互相看不到！

用单例:
  AppManager::instance().registerApp(app);   // main.cpp
  AppManager::instance().routeRequest(...);  // web_server.cpp
  → 始终是同一个对象，数据完全共享！
```

#### 本项目中使用单例模式的类

| 类 | 文件 | 用途 |
|----|------|------|
| `AppManager` | `application/app_manager.hpp` | 全局应用管理器 |
| `Logger` | `core/logger.hpp` | 全局日志系统 |

### 4.2 与单例模式相对的模式 - 工厂模式/多例模式

单例模式的核心特征是 **"全局唯一"**。与之相对的概念是 **"允许多个实例"**，对应的设计模式有：

#### (1) 多例模式 (Multiton Pattern)

```cpp
// 多例: 同一个类可以创建多个实例，通过 key 管理
class DeviceManager {
    static map<string, DeviceManager*> instances;
    
    static DeviceManager* getInstance(const string& key) {
        if (instances.find(key) == instances.end()) {
            instances[key] = new DeviceManager(key);
        }
        return instances[key];
    }
};

// 每个区域一个实例:
DeviceManager::getInstance("zone_A")->scan();
DeviceManager::getInstance("zone_B")->scan();
```

#### (2) 工厂模式 (Factory Pattern)

```cpp
// 工厂: 通过工厂方法创建不同类型的对象
class AppFactory {
public:
    static shared_ptr<AppBase> createApp(const string& type) {
        if (type == "security") return make_shared<AppSecurity>();
        if (type == "fire")     return make_shared<AppFireFighting>();
        if (type == "door")     return make_shared<AppDoorAccess>();
        return nullptr;
    }
};

// 创建多个不同实例:
auto app1 = AppFactory::createApp("security");
auto app2 = AppFactory::createApp("fire");
auto app3 = AppFactory::createApp("door");
```

#### 对比总结

```
┌──────────────┬────────────────────┬─────────────────────┐
│              │   单例 (Singleton)  │  多例/工厂 (Multi)   │
├──────────────┼────────────────────┼─────────────────────┤
│ 实例数量      │ 全局唯一 1 个      │ 可以有多个           │
│ 创建方式      │ 类自己管理         │ 外部调用者创建       │
│ 访问方式      │ 静态方法获取       │ new 或工厂方法创建   │
│ 构造函数      │ private/protected  │ public              │
│ 拷贝          │ 禁止               │ 通常允许             │
│ 典型应用      │ 管理器、日志、配置  │ 设备、传感器、应用   │
│ 本项目示例    │ AppManager, Logger │ AppSecurity, DevSmoke│
└──────────────┴────────────────────┴─────────────────────┘
```

在本项目中的体现：

```
单例 (全局唯一):
  AppManager::instance()     → 整个系统只有 1 个应用管理器
  Logger::instance()         → 整个系统只有 1 个日志系统

多例 (多个实例):
  DevSmoke  dev_smoke;       → 可以有多个烟雾传感器实例
  DevWater  dev_water;       → 可以有多个水浸传感器实例
  AppSecurity app_security;  → 理论上可以创建多个安防应用实例
                               (但当前只注册了 1 个)
```

### 4.3 模板方法模式 (Template Method)

**定义**: 在基类中定义算法骨架，将某些步骤延迟到子类实现。

```cpp
// 基类 AppBase 定义了应用的"算法骨架":
class AppBase {
public:
    virtual int init() { return 0; }      // 步骤1: 初始化 (子类可覆盖)
    virtual int start() {                  // 步骤2: 启动 (子类可覆盖)
        m_running = true;                  //   基类固定: 设置运行标志
        return 0;                          //   子类可扩展: 启动业务线程
    }
    virtual void stop() {                  // 步骤3: 停止 (子类可覆盖)
        m_running = false;                 //   基类固定: 清除运行标志
    }
};

// 子类 AppSecurity 覆盖了这些步骤:
class AppSecurity : public AppBase {
    int init() override {
        addLog("系统初始化"...);           // 子类自定义: 记录日志
        return 0;
    }
    int start() override {
        AppBase::start();                  // 先调用基类 (设置 m_running)
        m_pollThread = thread(...);        // 子类自定义: 启动轮询线程
        return 0;
    }
    void stop() override {
        if (m_running) {
            AppBase::stop();               // 先调用基类 (清除 m_running)
            m_pollThread.join();           // 子类自定义: 等待线程结束
        }
    }
};
```

### 4.4 策略模式 (Strategy Pattern)

**定义**: 定义一系列算法，将每个算法封装起来，使它们可以互换。

```cpp
// ApiHandler 就是策略模式的体现:
using ApiHandler = function<HttpResponse(const HttpRequest&)>;

// 每个 API 路由就是一个"策略":
registerApi("/api/status",  [this](auto& r){ return handleGetStatus(r); });
registerApi("/api/sensors", [this](auto& r){ return handleGetSensors(r); });
registerApi("/api/alarms",  [this](auto& r){ return handleGetAlarms(r); });
registerApi("/api/control", [this](auto& r){ return handlePostControl(r); });
registerApi("/api/logs",    [this](auto& r){ return handleGetLogs(r); });

// 运行时根据请求路径选择不同的"策略"执行:
for (const auto& route : m_apiRoutes) {
    if (request.path == route.first) {
        return route.second(request);  // 执行对应的策略
    }
}
```

### 4.5 观察者模式 (Observer Pattern)

**定义**: 当对象状态改变时，所有依赖它的对象都会被通知。

本项目中 `SecurityState` 使用 `atomic` 变量实现了类似观察者的效果：

```
传感器数据变化
    ↓
AppSecurity::pollingThread() 检测到变化
    ↓
evaluateRisk() 更新风险等级
    ↓
triggerAlarm() 通知联动设备 (灯光/警号/通风)
    ↓
addLog() 记录事件日志
    ↓
WebServer 通过 API 返回最新状态给前端
```
