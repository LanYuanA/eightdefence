# 多线程架构优化方案 V2.0

## 一、现有问题分析

### 1. 原始架构问题
- **单线程轮询**：所有设备串行轮询，一个设备超时会阻塞所有后续设备
- **写指令阻塞**：UI下发写指令需要等待当前轮询周期结束
- **无日志管理**：只有 printf 输出，无文件日志，无法追溯历史
- **无命令队列**：读写操作共享同一执行路径，无法区分优先级

### 2. 485总线约束
RS-485是**半双工总线**，同一时刻只能有一个节点发送数据。这意味着：
- 即使多线程并发，总线上的通信仍然是**串行**的
- 需要通过**互斥锁**保证总线访问的线程安全
- 多线程的价值在于：**等待时间不阻塞其他线程的逻辑处理**

## 二、已实现的优化

### 2.1 多线程轮询管理器 (PollingManager)

**架构图**：
```
┌─────────────────────────────────────────────────┐
│                   PollingManager                │
│                                                  │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐      │
│  │ 线程 #1  │  │ 线程 #2  │  │ 线程 #3  │ ...  │
│  │ 1s间隔   │  │ 5s间隔   │  │ 10s间隔  │      │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘      │
│       │              │              │            │
│       └──────────────┼──────────────┘            │
│                      │                           │
│              ┌───────▼───────┐                   │
│              │  SerialBus    │                   │
│              │  (互斥锁)     │                   │
│              └───────┬───────┘                   │
│                      │                           │
│              ┌───────▼───────┐                   │
│              │   RS-485 总线  │                   │
│              └───────────────┘                   │
└─────────────────────────────────────────────────┘
```

**核心特性**：
- 每个设备独立线程，互不影响
- 同一设备的多个寄存器合并为一次读取（减少总线事务）
- 每个设备可配置独立的轮询间隔
- 通过 SerialBus 互斥锁保证总线安全
- 每个线程组有独立的统计计数器

### 2.2 线程安全串口总线 (SerialBus)

**功能**：
- `acquire()` / `release()` 互斥锁
- `sendThenReceive()` 原子操作（发送+接收一步完成）
- 自动清空接收缓冲区（每次通信前清空，防止数据串扰）
- 总线级统计（事务数、错误数、延迟、争用次数）

### 2.3 线程安全 ModbusService

**功能**：
- 所有 Modbus 操作（读写寄存器/线圈）内部自动加锁
- 每个设备支持独立的超时和重试配置
- 统一的通信统计

## 三、新增功能：日志系统 (Logger)

### 3.1 设计目标
- 每次运行生成独立日志文件（带时间戳）
- 日志文件上限50个，自动清理最旧的
- 支持 INFO / WARNING / ERROR 三个级别
- 线程安全，多线程同时写入不冲突
- 同时输出到文件和控制台

### 3.2 使用方法

```cpp
#include "logger.hpp"

// 初始化（程序启动时调用一次）
Logger::instance().init("./logs", 50, LogLevel::INFO);

// 使用便捷宏
LOG_INFO("设备 %s 温度: %.1f°C", name, temp);
LOG_WARNING("轮询超时: 设备地址 0x%02X", addr);
LOG_ERROR("串口打开失败: %s", device);

// 关闭（程序退出时）
Logger::instance().shutdown();
```

### 3.3 日志文件格式
```
logs/
├── gateway_20260525_201630.log  (当前运行)
├── gateway_20260525_180000.log  (上次运行)
├── gateway_20260524_150000.log  (更早)
└── ... (最多50个)
```

日志行格式：
```
2026-05-25 20:16:30.123 [INFO] main.cpp:42 - 设备已初始化
2026-05-25 20:16:31.456 [WARN] polling_manager.cpp:128 - 轮询超时
2026-05-25 20:16:32.789 [ERROR] serial_bus.cpp:95 - 串口打开失败
```

## 四、新增功能：指令下发队列 (CommandQueue)

### 4.1 问题场景
当UI需要下发写指令时（如控制空调、灯光），如果直接调用 Modbus 写函数：
- 会与轮询线程争抢总线
- 如果轮询正在等待设备回复，写指令会被阻塞
- 无法区分指令优先级

### 4.2 解决方案：异步命令队列

**架构图**：
```
┌──────────────┐     ┌──────────────────────────────┐     ┌───────────┐
│   UI / Web   │────▶│       CommandQueue           │────▶│ SerialBus │
│  (提交命令)  │     │  ┌─────────────────────────┐  │     │  (互斥锁) │
└──────────────┘     │  │  优先级队列             │  │     └─────┬─────┘
                     │  │  URGENT > HIGH > NORMAL │  │           │
┌──────────────┐     │  └───────────┬─────────────┘  │     ┌─────▼─────┐
│   轮询线程   │────▶│              │                │     │  RS-485   │
│  (周期读取)  │     │  ┌───────────▼─────────────┐  │     │   总线    │
└──────────────┘     │  │  Worker Thread          │  │     └───────────┘
                     │  │  - 取出最高优先级命令    │  │
                     │  │  - 通过SerialBus执行     │  │
                     │  │  - 支持超时和重试        │  │
                     │  │  - 结果回调通知          │  │
                     │  └─────────────────────────┘  │
                     └──────────────────────────────┘
```

### 4.3 核心特性

| 特性 | 说明 |
|------|------|
| **异步非阻塞** | UI提交命令后立即返回，不等待执行完成 |
| **优先级队列** | URGENT > HIGH > NORMAL > LOW，紧急命令优先执行 |
| **重试机制** | 每个命令可配置最大重试次数和超时时间 |
| **结果查询** | 支持阻塞等待和非阻塞查询两种方式 |
| **完成回调** | 命令执行完成后自动调用回调函数 |
| **取消机制** | 可以取消队列中等待执行的命令 |
| **统计信息** | 记录提交数、执行数、成功率、平均耗时等 |

### 4.4 使用方法

```cpp
#include "command_queue.hpp"

// 创建并启动
CommandQueue cmdQueue(&serialBus, &modbusService, 1);
cmdQueue.start();

// 方式1: 异步提交 + 回调
cmdQueue.writeRegister(0x01, 0x0010, 250,
    CommandPriority::NORMAL,
    [](const CommandResult &r) {
        if (r.status == CommandStatus::SUCCESS) {
            printf("写入成功! 耗时: %.1fms\n", r.execTimeMs);
        }
    });

// 方式2: 异步提交 + 阻塞等待结果
uint64_t id = cmdQueue.writeRegister(0x01, 0x0010, 250);
CommandResult result = cmdQueue.waitResult(id, 5000);

// 方式3: 紧急命令 (最高优先级)
cmdQueue.writeCoil(0x01, 0x0001, true, CommandPriority::URGENT);

// 停止
cmdQueue.stop();
```

### 4.5 读写分离保证

```
时间线:
─────┬─────┬─────┬─────┬─────┬─────┬─────▶
     │     │     │     │     │     │
轮询: │R1   │R2   │R3   │     │R4   │R5    (R=Read, 周期性)
     │     │     │     │     │     │
写入: │     │     │  W1 │     │     │      (W=Write, 异步插入)
     │     │     │     │     │     │
总线: │[R1] │[R2] │[W1] │[R3] │[R4] │[R5]  (实际总线序列)
```

写指令在轮询间隙执行，不会丢失轮询（只是延迟一轮），也不会阻塞轮询线程。

## 五、压力测试

### 5.1 测试模式

使用 `-t` 参数启动压力测试：

```bash

# 压力测试60秒，8并发
./app_gateway -t 60 -c 8
```

### 5.2 测试项目

| 测试项 | 说明 |
|--------|------|
| **吞吐量测试** | 单线程最大通信速率（事务/秒） |
| **并发争用测试** | 多线程同时访问总线的争用情况 |
| **快速轮询极限测试** | 最小延迟下的极限轮询频率 |
| **持续稳定性测试** | 长时间运行的稳定性和错误率 |

```cpp
}
```

## 八、编译和运行

```bash
# 编译
make clean && make

# 正常运行
./app_gateway -d /dev/ttyS9 -b 9600 -w 4

# 压力测试
./app_gateway -t 30 -c 8

# 查看日志
tail -f logs/gateway_*.log
```

### 命令行参数

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `-d <device>` | 串口设备路径 | `/dev/ttyS9` |
| `-b <baud>` | 波特率 | `9600` |
| `-w <threads>` | 工作线程数 | `4` |
| `-t <seconds>` | 压力测试持续时间 | `0`（不测试） |
| `-c <count>` | 压力测试并发线程数 | `4` |
