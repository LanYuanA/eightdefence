# 应用独立日志与安防传感器离线检测改造记录

## 1. 改造概述

本次改造完成两项功能：

1. **应用独立日志系统** — 每个应用拥有独立的日志文件，主日志仅保留系统级日志
2. **安防传感器离线检测** — 设备未接入时正确显示离线状态，不再误报"一切正常"

## 2. 应用独立日志系统

### 2.1 需求背景

原有系统只有一个全局 Logger（单例），所有日志写入 `logs/gateway_YYYYMMDD_HHMMSS.log`。用户希望：
- 主日志保留系统级日志
- 每个应用有独立的日志文件
- 应用日志放在 `logs/{appName}/` 子目录下

### 2.2 日志目录结构

```
logs/
├── gateway_20260526_100507.log    # 主日志 (仅系统级事件)
├── security/                      # 安防应用专属目录
│   ├── security_20260526_100507.log
│   └── security_20260526_100054.log
├── fire/                          # 消防应用目录 (未来)
│   └── fire_*.log
└── ...
```

### 2.3 新增文件

#### `core/app_logger.hpp` — 应用日志器类

```cpp
class AppLogger {
public:
    AppLogger(const std::string& appName, const std::string& logDir = "./logs");
    ~AppLogger();
    int init();
    void shutdown();
    void log(LogLevel level, const char *file, int line, const char *fmt, ...);
    void logV(LogLevel level, const char *file, int line, const char *fmt, va_list args);
private:
    std::string appName_;
    std::string logDir_;
    std::string appDir_;         // logs/{appName}/
    std::string currentLogFile_;
    std::ofstream fileStream_;
    std::mutex mtx_;
    bool initialized_ = false;
};
```

**便捷宏**（在 AppBase 子类中使用）：

```cpp
APP_LOG_INFO("初始化完成, 路由: %s", m_routePrefix.c_str());
APP_LOG_WARNING("设备离线: %s", name);
APP_LOG_ERROR("通信失败: %s", err);
```

#### `core/app_logger.cpp` — AppLogger 实现

- `init()`: 创建 `logs/{appName}/` 子目录，创建 `{appName}_YYYYMMDD_HHMMSS.log` 文件
- `logV()`: 仅写入应用专属日志文件（不写入主系统日志）
- 日志格式与主日志一致：`YYYY-MM-DD HH:MM:SS.mmm [LEVEL] file:line - message`

#### `application/app_base.cpp` — AppBase 实现

```cpp
AppBase::~AppBase() {
    if (m_logger) { delete m_logger; m_logger = nullptr; }
}

int AppBase::initLogger(const std::string& logDir) {
    if (m_logger) return 0;
    m_logger = new AppLogger(m_name, logDir);
    return m_logger->init();
}
```

### 2.5 Web API 变更

返回结果现在包含子目录路径：

## 3. 安防传感器离线检测

### 3.1 问题描述

设备未接入时，安防应用的状态API返回：

```json
{
    "system": { "overallRisk": "低风险", "systemNormal": true },
    "water": { "risk": "低风险" },
    "intrusion": { "risk": "低风险" }
}
```

实际应该是"设备离线"状态，而非"一切正常"。

### 3.2 根因分析

**问题A — 传感器默认值与"安全"值无法区分：**

设备读取失败时，驱动函数直接 `return`，不更新状态变量。状态变量保持初始值 `0`，而 `0` 恰好是"无报警/正常/安全"的含义。

**问题B — 风险计算不检查设备在线状态：**

```cpp
SecurityRiskLevel calcWaterRisk(float level, int sensorState) {
    if (sensorState != 0 || level > 3.0f) return HIGH;
    if (level > 1.0f) return MEDIUM;
    return LOW;   // sensorState==0 时命中这里
}
```

`DeviceStatusCpp` 虽然跟踪了 `online` 状态，但风险计算完全忽略了它。

### 3.3 修复方案

修改 `application/apps/security/app_security.cpp`：

#### 3.3.1 `evaluateRisk()` 增加设备在线检查

```cpp
void AppSecurity::evaluateRisk(int waterState, int irState, int radarState) {
    bool waterOnline = dev_water.isOnline();
    bool irOnline = dev_infrared.isOnline();

    m_state.waterRisk = calcWaterRisk(m_state.waterLevel.load(), waterState);
    m_state.intrusionRisk = calcIntrusionRisk(irState, radarState);
    m_state.gasRisk = calcGasRisk(m_state.gasConcentration.load());

    // 设备离线时, 对应子系统标记为中风险
    if (!waterOnline) m_state.waterRisk = SecurityRiskLevel::MEDIUM;
    if (!irOnline) m_state.intrusionRisk = SecurityRiskLevel::MEDIUM;

    int maxRisk = std::max({...});
    m_state.overallRisk = static_cast<SecurityRiskLevel>(maxRisk);

    // 设备离线或有风险时, 系统不正常
    bool allOnline = waterOnline && irOnline;
    m_state.systemNormal.store(maxRisk == 0 && allOnline);
}
```

#### 3.3.2 API 响应增加 `online` 字段

`handleGetStatus()` 和 `handleGetSensors()` 返回的 JSON 增加 `online` 字段：

```json
{
    "system": { "overallRisk": "中风险", "systemNormal": false },
    "water": { "online": false, "risk": "中风险" },
    "intrusion": { "online": false, "risk": "中风险" }
}
```

前端可根据 `online` 字段显示"设备离线"提示。

### 3.4 修复效果

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 设备全部离线 | 低风险 / 系统正常 | 中风险 / 系统异常 |
| 水浸传感器离线 | 低风险 | 中风险 / water.online=false |
| 红外探测器离线 | 低风险 | 中风险 / intrusion.online=false |
| 设备在线 + 无报警 | 低风险 / 系统正常 | 低风险 / 系统正常 |

## 4. 设备手动控制 API

### 4.1 需求背景

用户需要在安防页面手动开启/关闭设备（水浸传感器、红外探测器），以便测试离线检测功能或临时禁用设备。

### 4.2 设备控制接口

#### `GET /api/device/control?device={name}&action={enable|disable}`

| 参数 | 说明 |
|------|------|
| `device` | 设备名称：`water`（水浸传感器）、`infrared`（红外探测器） |
| `action` | `enable` 启用设备 / `disable` 禁用设备 |

响应：
```json
{ "ok": true, "device": "water", "action": "disable" }
```

### 4.3 底层实现

#### `DeviceStatusCpp::forceOffline()` — 新增方法

```cpp
void forceOffline() {
    std::lock_guard<std::mutex> lock(mtx);
    online = 0;
}
```

#### `DevWater::setOnline()` / `DevInfrared::setOnline()` — 新增方法

```cpp
void setOnline(bool online) {
    if (online) status_.onSuccess();
    else status_.forceOffline();
}
```

调用 `setOnline(true)` 将设备标记为在线并重置失败计数，`setOnline(false)` 强制标记为离线。

### 4.4 web_server.cpp 路由

```cpp
} else if (req.find("GET /api/device/control") == 0) {
    std::string device = get_query_param(req, "device");
    std::string action = get_query_param(req, "action");
    bool ok = false;
    if (device == "water") {
        if (action == "enable") { dev_water.setOnline(true); ok = true; }
        else if (action == "disable") { dev_water.setOnline(false); ok = true; }
    } else if (device == "infrared") {
        if (action == "enable") { dev_infrared.setOnline(true); ok = true; }
        else if (action == "disable") { dev_infrared.setOnline(false); ok = true; }
    }
    // 返回 JSON 响应
}
```

### 5.4 日志列表排序修复

**问题**: `security/security_*.log` 按字母排序排在 `gateway_*.log` 前面，导致日志页面实时标签显示在安防日志上。

**修复**: `web_server.cpp` 中日志列表排序改为 gateway 日志优先：

```cpp
std::sort(files.begin(), files.end(), [](const std::string& a, const std::string& b) {
    bool aGw = (a.find("gateway") == 0);
    bool bGw = (b.find("gateway") == 0);
    if (aGw != bGw) return aGw > bGw;  // gateway 排前面
    return a > b;
});
```

## 8. 有害气体安全防护 — 接入云测仪真实传感器

### 8.1 需求背景

原有有害气体模块使用模拟的 `gasConcentration` 单一数值。云测仪（DevCloud*）已有 TVOC、CH2O、O3、CO2 四种有害气体传感器，需要接入真实数据，超出安全阈值时触发报警。

### 8.2 传感器与阈值

| 传感器 | 全局变量 | 单位 | 中风险阈值 | 高风险阈值 |
|--------|---------|------|-----------|-----------|
| TVOC (挥发性有机物) | `dev_tvoc` | ppb | >200 | >500 |
| CH2O (甲醛) | `dev_ch2o` | ppb | >50 | >100 |
| O3 (臭氧) | `dev_o3` | ppb | >60 | >100 |
| CO2 (二氧化碳) | `dev_co2` | ppm | >800 | >1000 |

阈值依据：GB/T 18883 室内空气质量标准。

### 8.3 后端改动

#### `app_security.hpp`

- SecurityState 中移除 `gasConcentration`，新增 `gasSimulated` 标志和模拟值缓存
- `calcGasRisk(int)` 替换为 `calcSingleGasRisk(int, int, int)` 通用版本

#### `app_security.cpp`

**`handleGetStatus()`** — 读取四个真实传感器值，返回结构化 JSON：

```json
"gas": {
  "online": true,
  "tvoc": { "value": 120, "unit": "ppb", "online": true },
  "ch2o": { "value": 30, "unit": "ppb", "online": true },
  "o3": { "value": 45, "unit": "ppb", "online": true },
  "co2": { "value": 450, "unit": "ppm", "online": true },
  "risk": "低风险",
  "ventilationActive": false
}
```

**`evaluateRisk()`** — 气体风险 = 所有在线传感器中的最高风险。全部离线时标记为中风险。

**模拟机制** — `gasSimulated` 为 true 时使用 state 中的模拟值，否则读取真实传感器。模拟时设置所有传感器为高风险值，重置时恢复为读取真实数据。

### 8.4 前端改动

#### Security.vue

有害气体卡片改为显示四个传感器实时读数：

```

├── TVOC (挥发性有机物)   120 ppb
├── CH2O (甲醛)           30 ppb
```
