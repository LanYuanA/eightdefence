# 日志系统说明

## 1. 概述

项目采用双层日志架构：

1. **主系统日志** (`Logger` 单例) — 记录系统级事件（串口、轮询、设备驱动等）
2. **应用独立日志** (`AppLogger`) — 每个应用拥有独立的日志文件

### 核心特性

- **线程安全**: 内部使用 `std::mutex`，多线程同时写日志不会产生数据竞争
- **双输出**: 主日志同时写入日志文件和控制台（stdout/stderr）
- **自动轮转**: 日志文件上限 50 个，自动删除最旧的
- **时间戳文件名**: 每次启动生成独立日志文件，格式 `gateway_YYYYMMDD_HHMMSS.log`
- **三级日志**: INFO（信息）、WARNING（警告）、ERROR（错误）
- **毫秒精度**: 日志时间戳精确到毫秒 `YYYY-MM-DD HH:MM:SS.mmm`
- **应用独立日志**: 每个应用（安防、消防等）拥有独立的日志文件和子目录

## 2. 日志文件存储

### 2.1 存储位置

日志文件默认存放在程序运行目录下的 `./logs/` 文件夹中。

```
eightdefence/
├── gateway          # 主程序
└── logs/                    # 日志目录
    ├── gateway_20260526_100507.log   # 主系统日志
    ├── gateway_20260526_100054.log
    ├── security/                      # 安防应用日志目录
    │   ├── security_20260526_100507.log
    │   └── security_20260526_100054.log
    ├── fire/                          # 消防应用日志目录 (未来)
    │   └── fire_*.log
    └── ...
```

### 2.2 文件命名规则

格式: `gateway_YYYYMMDD_HHMMSS.log`

示例: `gateway_20260525_201630.log` 表示 2026年5月25日 20:16:30 启动的日志。

### 2.3 文件上限

默认最多保留 **50** 个日志文件。当日志文件数量超过上限时，系统会自动删除文件名最旧的文件（文件名按字典序排序，等同于时间排序）。

## 3. 日志格式

每条日志的一般格式：

```
2026-05-25 20:16:30.123 [INFO] serial_bus.cpp:85 - 串口 /dev/ttymxc2 已打开 (115200-8N1)
2026-05-25 20:16:30.456 [WARN] polling_manager.cpp:203 - 设备 PM2.5 传感器 连续失败 3 次
2026-05-25 20:16:30.789 [ERROR] modbus_core.c:156 - 串口发送失败: 写入错误
```

各字段含义：

| 字段 | 说明 | 示例 |
|------|------|------|
| 时间戳 | 精确到毫秒 | `2026-05-25 20:16:30.123` |
| 级别 | `[INFO]` / `[WARN]` / `[ERROR]` | `[INFO]` |
| 源文件 | 发生日志的源文件名（不含路径） | `serial_bus.cpp` |
| 行号 | 源文件中的行号 | `85` |
| 消息 | 日志内容 | `串口 /dev/ttymxc2 已打开` |

### 日志文件头

每次启动时，日志文件开头会写入：

```
======================================================
  日志系统启动: 2026-05-25 20:16:30.000
  日志文件: ./logs/gateway_20260525_201630.log
  最大文件数: 50
  最低级别: INFO
======================================================
```

程序正常退出时，日志文件结尾会写入：

```
======================================================
  日志系统关闭: 2026-05-25 21:30:00.000
======================================================
```

## 4. 日志级别

### 4.1 主系统日志宏

| 级别 | 宏 | 用途 | 控制台输出 |
|------|-----|------|-----------|
| INFO | `LOG_INFO(fmt, ...)` | 正常运行信息：启动、设备轮询结果、命令执行 | stdout |
| WARNING | `LOG_WARNING(fmt, ...)` | 异常但可恢复：设备超时、数据校验失败、连接断开 | stdout |
| ERROR | `LOG_ERROR(fmt, ...)` | 严重错误：串口打开失败、硬件故障、不可恢复的错误 | stderr |

### 4.2 应用独立日志宏

在 AppBase 子类中使用（需包含 `app_logger.hpp`）：

| 级别 | 宏 | 用途 |
|------|-----|------|
| INFO | `APP_LOG_INFO(fmt, ...)` | 应用生命周期、业务事件 |
| WARNING | `APP_LOG_WARNING(fmt, ...)` | 告警事件、风险评估 |
| ERROR | `APP_LOG_ERROR(fmt, ...)` | 应用级错误 |

应用日志仅写入应用专属日志文件（如 `logs/security/security_*.log`），不写入主系统日志。

### 4.3 使用方法

**主系统日志**（在任何模块中使用）：

```cpp
#include "logger.hpp"

LOG_INFO("系统启动完成, 共注册 %d 个设备", deviceCount);
LOG_WARNING("设备 %s (地址 0x%02X) 响应超时", devName, devAddr);
LOG_ERROR("串口 %s 打开失败: %s", port, strerror(errno));
```

**应用独立日志**（在 AppBase 子类中使用）：

```cpp
#include "app_logger.hpp"

// 生命周期日志
APP_LOG_INFO("初始化完成, 路由: %s", m_routePrefix.c_str());
APP_LOG_INFO("已停止");

// 业务事件日志
APP_LOG_WARNING("水浸风险警报: 检测到水位异常(5.8cm)");
APP_LOG_ERROR("传感器通信失败: %s", err);
```

### 4.4 控制台颜色区分

在终端中查看日志时：
- **INFO** 日志输出到 stdout（正常颜色）
- **WARNING** 日志输出到 stdout（正常颜色）
- **ERROR** 日志输出到 stderr（红色高亮，可被 `2>&1` 重定向捕获）

## 5. 初始化与配置

### 5.1 初始化

日志系统在 `main.cpp` 中初始化，一般不需要手动修改：

```cpp
// 初始化日志系统
Logger::instance().init();  // 使用默认参数: ./logs, 50个文件, INFO级别
```

### 5.2 自定义参数

```cpp
Logger::instance().init(
    "./my_logs",           // 自定义日志目录
    100,                   // 最多保留100个文件
    LogLevel::WARNING      // 只记录 WARNING 和 ERROR
);
```

### 5.3 运行时调整级别

```cpp
// 运行时临时降低日志级别（只记录 ERROR）
Logger::instance().setMinLevel(LogLevel::ERROR_);

// 恢复正常
Logger::instance().setMinLevel(LogLevel::INFO);
```

## 6. Web API 查看日志

后端 HTTP 服务器提供了 3 个日志相关 API，可在浏览器或前端页面中查看日志。

### 6.1 获取日志文件列表

```
GET /api/logs/list
```

返回 JSON 数组，包含主日志和应用子目录日志，按文件名降序排列（最新的在前）：

```json
[
    "security/security_20260526_100507.log",
    "gateway_20260526_100507.log",
    "gateway_20260526_100054.log"
]
```

### 6.2 获取最新日志

```
GET /api/logs/latest
```

返回最新日志文件的完整内容（纯文本）。自动扫描主日志目录和所有应用子目录，返回最新的文件。如果没有日志文件，返回 `[]`。

### 6.3 获取指定日志文件

```
GET /api/logs/{path}
```

例如:
- `GET /api/logs/gateway_20260525_201630.log` — 主日志
- `GET /api/logs/security/security_20260526_100507.log` — 安防应用日志

返回指定日志文件的完整内容（纯文本）。

**安全限制**: 路径中不能包含 `..`，防止路径遍历攻击。

### 6.4 前端日志查看页面

系统提供了 Vue 前端日志查看页面（`/logs` 路由），功能包括：

- 左侧显示日志文件列表，自动检测最新文件并标记 LIVE 标签
- 右侧显示日志内容，支持按级别过滤（INFO / WARNING / ERROR）
- 支持关键字搜索并高亮匹配
- 每 5 秒自动刷新最新日志
- 显示统计信息：总行数、过滤行数、错误数、警告数、文件大小
- 错误行红色高亮、警告行黄色高亮

## 7. 日志在代码中的分布

以下是系统中各模块的关键日志点：

### 7.1 SerialBus（串口总线层）

| 场景 | 级别 | 说明 |
|------|------|------|
| 串口打开成功 | INFO | 输出端口名和波特率 |
| 串口打开失败 | ERROR | 输出端口名和错误原因 |
| 帧发送 | INFO | 输出目标地址和功能码 |
| 帧接收 | INFO | 输出源地址和数据长度 |
| 发送失败 | ERROR | 串口写入错误 |
| 接收超时 | WARNING | 等待响应超时 |
| CRC 校验失败 | WARNING | 输出期望值和实际值 |
| 缓冲区溢出 | WARNING | 数据超长截断 |
| 总线冲突等待 | WARNING | 被阻塞时输出 |
| 总线统计 | INFO | 每 60 秒输出总线健康数据 |

### 7.2 PollingManager（轮询管理层）

| 场景 | 级别 | 说明 |
|------|------|------|
| 启动 | INFO | 输出设备数和轮询间隔 |
| 停止 | INFO | 停止轮询 |
| 单次轮询 | INFO | 输出设备地址、结果、耗时、重试次数 |
| 设备超时 | WARNING | 输出连续失败次数 |
| 设备离线 | ERROR | 连续失败超阈值 |
| 设备恢复 | INFO | 从离线恢复到在线 |
| 配置更新 | INFO | 更新设备轮询间隔 |

### 7.3 ParseService（数据解析层）

| 场景 | 级别 | 说明 |
|------|------|------|
| 命令提交 | INFO | 输出设备地址、功能码、队列大小 |
| 命令执行 | INFO | 输出事务 ID、耗时、结果 |
| 命令失败 | ERROR | 输出失败原因 |
| 队列满 | WARNING | 队列容量不足 |
| 超时命令清理 | WARNING | 清理数量 |
| 统计输出 | INFO | 每 60 秒输出队列健康数据 |

### 7.4 核心层（modbus_core.c）

| 场景 | 级别 | 说明 |
|------|------|------|
| 通信成功 | INFO | 事务 ID、设备地址、耗时 |
| 发送失败 | ERROR | 串口写入错误 |
| 无响应 | WARNING | 设备地址、超时时间 |
| CRC 校验错误 | WARNING | 设备地址、期望/实际 CRC |
| 异常响应 | WARNING | Modbus 异常码 |

## 8. 日志文件管理

### 8.1 手动清理

```bash
# 查看日志文件数量
ls -la ./logs/*.log | wc -l

# 删除 7 天前的日志
find ./logs -name "*.log" -mtime +7 -delete

# 只保留最新的 10 个日志
ls -t ./logs/*.log | tail -n +11 | xargs rm -f
```

### 8.2 实时查看日志

```bash
# 实时跟踪最新日志
tail -f ./logs/gateway_*.log | tail -1

# 查看最新日志文件
less ./logs/$(ls -t ./logs/*.log | head -1)

# 过滤 ERROR 级别
grep "\[ERROR\]" ./logs/*.log

# 过滤 WARNING 级别
grep "\[WARN\]" ./logs/*.log

# 统各级别日志数量
grep -c "\[INFO\]" ./logs/*.log
grep -c "\[WARN\]" ./logs/*.log
grep -c "\[ERROR\]" ./logs/*.log
```

### 8.3 日志磁盘占用估算

每条日志约 100-200 字节。以每秒 10 条日志计算：

| 时长 | 预估大小 |
|------|---------|
| 1 小时 | ~5 MB |
| 24 小时 | ~120 MB |
| 50 个文件（按默认轮转） | 取决于运行时间 |

默认 50 个文件的上限可以有效防止磁盘被写满。

## 9. 常见问题

### Q: 日志文件在哪里？

程序运行目录下的 `./logs/` 文件夹。如果程序在 `/home/kylin/eightdefence/` 目录运行，日志在 `/home/kylin/eightdefence/logs/`。

### Q: 如何查看实时日志？

1. **终端**: `tail -f ./logs/gateway_*.log`（注意通配符可能匹配不到最新文件，建议用具体文件名）
2. **Web 前端**: 访问 `http://设备IP:8080/logs`（Vue 日志查看页面）
3. **API**: `curl http://设备IP:8080/api/logs/latest`

### Q: 日志太多怎么办？

1. 调低日志级别: `Logger::instance().setMinLevel(LogLevel::WARNING);`（只记录警告和错误）
2. 减少最大文件数: `Logger::instance().init("./logs", 10);`（只保留 10 个文件）
3. 手动清理: `find ./logs -name "*.log" -mtime +3 -delete`（删除 3 天前的日志）

### Q: 日志写入会影响性能吗？

日志使用互斥锁保证线程安全，在高并发场景下可能成为瓶颈。当前实现每条日志都 flush 到磁盘，确保程序崩溃时不丢失日志。如果性能成为问题，可以考虑：
- 使用异步日志（缓冲写入，定期 flush）
- 减少日志输出频率
- 降低日志级别

### Q: 如何在新模块中添加日志？

1. 包含头文件: `#include "logger.hpp"`
2. 使用宏: `LOG_INFO("...")`、`LOG_WARNING("...")`、`LOG_ERROR("...")`
3. 无需手动初始化，Logger 是全局单例
