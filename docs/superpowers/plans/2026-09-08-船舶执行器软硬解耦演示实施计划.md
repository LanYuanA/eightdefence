# 船舶执行器软硬解耦演示 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增一个适合 1920×1080 会议大屏的硬件解耦演示页面，通过三台不同 RS485 地址的电机展示应用与原子服务不变、操作员一键确认完成底层执行器替换。

**Architecture:** 用独立 TypeScript 状态模型表达电机在线、异常、候选发现、人工确认、绑定迁移和任务恢复；Vue 页面只负责可视化和触发状态事件。页面默认运行纯前端模拟，同时通过明确的模式边界为后端真实设备状态接口预留接入点，不在浏览器中拼装或发送 Modbus 控制报文。

**Tech Stack:** Vue 3、TypeScript 6、Vue Router、原生 CSS、Node.js test runner、Vite

**Spec:** `docs/superpowers/specs/2026-09-08-船舶执行器软硬解耦演示方案.md`

## Global Constraints

- 采用方案 A：系统发现兼容备用电机后，由操作员点击“确认切换”。
- 三台演示电机地址固定为 `0x02`、`0x0E`、`0x0F`，上层统一调用逻辑执行器 `VENT-01`。
- 页面默认是演示模式，不执行 `./test`，不访问串口，不发送真实电机控制命令。
- 层级固定为“应用 → 原子服务 → 设备抽象层 → 执行器硬件”；态势感知与执行器硬件在系统总图中处于同一底层。
- 替换过程中应用修改数和原子服务修改数保持 0，只更新一次设备绑定。
- 短电机和长电机只在演示状态模型中视为兼容，真实接入必须由后端能力校验。
- 保持现有软件组合、多个应用并行运行和传感器数据功能不变。
