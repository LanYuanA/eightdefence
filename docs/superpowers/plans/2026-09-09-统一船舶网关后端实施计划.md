# 统一船舶网关后端实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 C++ 网关持久化并调度船舶软件定义应用，通过 `/api/v1` 向前端提供统一的应用、任务、设备绑定和安全控制状态。

**Architecture:** 在 `application/marine/` 新增可单独测试的领域模块，`MarineRuntime` 在独立线程中推进多个任务实例，`MarineRepository` 使用 JSON 文件持久化定义和摘要，`MarineExecutor` 对现有传感器对象提供只读适配并把执行服务固定为模拟输出。`MarineApi` 接收 HTTP 请求并返回领域 JSON，`web_server.cpp` 只解析 HTTP 方法、路径和正文后转发请求；原路由不改动。

**Tech Stack:** C++17、POSIX pthread、现有轻量 HTTP 服务器、Node.js test runner、Vue 3、TypeScript、Vite。

**Spec:** `docs/superpowers/specs/2026-09-09-统一船舶网关后端设计.md`

## Global Constraints

- 不新增 Node.js、数据库或第三方 C++ 运行时依赖；离线麒麟 ARM64 环境必须能用 `make` 构建。
- 新接口必须使用 `/api/v1/...`；既有 `/api/data`、`/security/api/...`、`/environment/api/...`、`/fire/api/...` 路由和响应保持可用。
- 所有执行控制默认锁定且 `actuatorControlEnabled=false`；第一阶段不得向命令队列或串口写入任何任务执行命令。
- 应用和原子服务不得保存 RS485 地址；绑定只能由逻辑执行器 ID 指向物理设备 ID。
- 网关重启时，任何持久化为 `running` 或 `paused` 的实例必须恢复为 `interrupted`，不得自动继续。
- 每一个新生产函数先由 `tests/marine_backend_test.cpp` 或 `ui/tests/marine-api.test.mjs` 的失败测试定义，再写实现。

## Plan Self-Review
