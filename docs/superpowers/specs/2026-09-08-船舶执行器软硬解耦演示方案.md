# 船舶执行器软硬解耦演示方案

## 1. 文档目的

本文记录民用舰船软件定义演示中的“执行器软硬解耦”方案。方案采用 **A：操作员一键确认切换**。

演示目标是让观看者直观看到：船舶应用调用的是稳定的逻辑执行器能力，而不是某一个固定地址的物理电机。当当前电机离线或异常、另一台兼容电机接入后，设备抽象层只更新逻辑执行器与物理电机的绑定，应用、原子服务和任务编排均不修改；操作员确认后，任务从新的物理电机继续执行。

本阶段先完成方案与前端模拟设计。真实接入时，串口通信、状态轮询和控制命令必须由后端执行器适配器完成，浏览器不直接运行 `./test`，本文也不执行任何真实电机指令。

## 2. 已知设备条件

三台电机共用 RS485 串口 `/dev/ttyS9`，通信参数为 9600 波特率、500 ms 超时，物理地址分别为：

| 演示名称 | 类型 | RS485 地址 | 建议物理标识 |
| --- | --- | --- | --- |
| 海风一号 | 短电机 | `0x02` | MOTOR-02 |
| 海岳一号 | 长电机 | `0x0E` | MOTOR-0E |
| 海岳二号 | 长电机 | `0x0F` | MOTOR-0F |

以上名称用于会议大屏展示，可在实现前调整。短电机与长电机是否具有相同额定能力、转向和机械接口，仍需实机验证。系统只能在能力契约匹配时允许替换，不能仅因协议相同就认定可互换。

## 3. “不同地址但免修改替换”的实现原理

系统不把 `0x02`、`0x0E` 或 `0x0F` 写入应用和原子服务，而是引入稳定的逻辑执行器标识，例如：

```text
逻辑执行器：VENT-01（舱室通风执行器）
能力契约：启停、速度设定、运行状态、故障反馈
当前绑定：MOTOR-02 / ttyS9 / 0x02
```

调用关系固定为：

```text
应用
  ↓ 调用“舱室通风”原子服务
原子服务
  ↓ 请求逻辑执行器 VENT-01
设备抽象层
  ↓ 查询当前绑定并适配协议地址
RS485 物理电机（0x02、0x0E 或 0x0F）
```

替换电机时只把设备注册表中的绑定从 `MOTOR-02` 更新为 `MOTOR-0E` 或 `MOTOR-0F`。后端适配器在发送帧时填入新地址，所以上层应用不需要重新编排，原子服务不需要改代码，任务参数也不需要改。

这里的“免修改”具体指：

- 不修改应用页面和任务编排；
- 不修改原子服务调用对象；
- 不修改任务中保存的业务参数；
- 不人工改写程序中的串口地址；
- 只通过设备抽象层完成兼容性校验和运行时重新绑定。

它不表示三台物理电机使用相同地址，也不要求给新电机改地址。

## 4. 说明书中可用于状态识别的指令

依据《42一体伺服 RS485 型使用手册》IDS42-R V1.3，可用 Modbus `0x03` 功能码读取只读寄存器。以下请求沿用现有 `./test` 工具的报文格式，未在参数中列出 CRC；需要先确认该工具会自动追加并校验 CRC。

### 4.1 在线与驱动器状态：`6041h`

`6041h` 为状态字，类型 U16、只读，用于反映当前驱动器状态。建议将它作为在线探测的主要心跳：

```bash
./test /dev/ttyS9 020360410001 9600 500
./test /dev/ttyS9 0E0360410001 9600 500
./test /dev/ttyS9 0F0360410001 9600 500
```

收到地址、功能码、字节数和 CRC 均有效的响应，表示对应地址在线。单次超时只记为通信抖动；连续 3 次超时、CRC 错误或非法响应后，状态转为离线。恢复收到连续 2 次有效响应后，状态转为在线待检。

### 4.2 当前故障码：`603Fh`

`603Fh` 为当前故障码，类型 U16、只读：

```bash
./test /dev/ttyS9 0203603F0001 9600 500
./test /dev/ttyS9 0E03603F0001 9600 500
./test /dev/ttyS9 0F03603F0001 9600 500
```

说明书列出的主要值如下：

| 值 | 含义 |
| --- | --- |
| `0x0000` | 无故障 |
| `0x2212` | 硬件过流 |
| `0x3211` | 过压 |
| `0x3221` | 欠压 |
| `0x8311` | 过载 |
| `0x4201` | 过温度 |
| `0x8611` | 超差 |
| `0x7121` | 堵转 |
| `0x2211` | 软件过流 |
| `0x7310` | 超速 |
| `0x7320` | 编码器故障 |

返回非零值时，设备应显示为“异常”，停止向它分配新任务，并进入待切换流程。

### 4.3 电机运行状态：`2009h`

`2009h` 为电机状态查询寄存器，类型 U16、只读；`0` 表示静止，`1` 表示运行：

```bash
./test /dev/ttyS9 020320090001 9600 500
./test /dev/ttyS9 0E0320090001 9600 500
./test /dev/ttyS9 0F0320090001 9600 500
```

该状态用于在界面上区分“在线空闲”和“在线运行”，不能单独用于判断设备在线。

### 4.4 可选运行数据

说明书还提供：

- `6061h`：当前运行模式；
- `6064h`：实际位置，I32；
- `606Ch`：当前速度，I32，范围 -3000～3000 rpm。

`606Ch` 的数据类型为 I32，按 Modbus 常规应读取两个 16 位寄存器，但说明书示例中的读取数量存在不一致。该项只能在实机核对返回帧和高低字顺序后接入，不能先用于切换判断。

## 5. A 方案：操作员一键确认切换

### 5.1 选择理由

A 方案兼顾演示效果与设备安全：系统自动发现在线设备、识别故障并推荐兼容备用电机，但不会在无人确认时直接驱动刚接入的硬件。领导可以清楚看到应用保持不变、绑定发生变化、任务恢复三个关键动作。

### 5.2 完整状态流程

1. 后端每 500 ms 轮询三个已登记地址的 `6041h`。
2. 当前绑定电机连续 3 次无有效响应时，标记为“离线”；`603Fh` 非零时，标记为“异常”。
3. 调度器暂停该逻辑执行器的新控制下发，并保存当前任务上下文，包括应用、原子服务、任务参数和执行进度。
4. 系统扫描其余已登记地址，读取 `6041h`、`603Fh` 和 `2009h`。
5. 对在线、无故障、空闲且能力契约匹配的电机生成替换建议。
6. 前端显示“发现兼容电机”，突出推荐设备、原设备和预计恢复路径。
7. 操作员点击“确认切换”。后端再次做在线、无故障、空闲和能力校验。
8. 设备抽象层原子更新 `VENT-01` 的绑定，并记录切换前后地址、原因、时间和操作结果。
9. 后端先完成新电机初始化和参数核对，再恢复控制。不得直接把旧电机的最后一条原始报文盲目重发给新电机。
10. 应用页面继续显示同一个应用和同一个原子服务，数据流动画只在设备抽象层以下切换到新电机，并显示恢复耗时。

### 5.3 状态机

```text
在线空闲 ──收到任务──> 在线运行
   │                    │
   │连续通信失败         │连续通信失败 / 故障码非零
   ↓                    ↓
离线 / 异常 ──发现兼容设备──> 待确认切换
                                  │
                         操作员确认并复检
                                  ↓
                              切换初始化
                                  │
                      初始化成功 │ 初始化失败
                                  ↓
                         已恢复 / 切换失败
```

如果原设备在待确认期间恢复，不自动抢回绑定；界面同时显示“原设备已恢复”和“备用设备可用”，由操作员选择，避免绑定来回抖动。

## 6. 能力契约与替换条件

地址只是通信标识，不能证明设备可互换。每台电机需要在设备注册表中声明：

| 字段 | 示例 | 作用 |
| --- | --- | --- |
| `deviceId` | `MOTOR-0E` | 稳定的物理设备标识 |
| `bus` | `/dev/ttyS9` | 所属总线 |
| `address` | `0x0E` | Modbus 地址 |
| `model` | `IDS42-R` | 设备型号 |
| `capabilities` | 启停、速度、状态、故障 | 能力匹配 |
| `mechanicalProfile` | 长轴/短轴、转向、额定参数 | 机械与性能匹配 |
| `availability` | 在线、离线、异常、待检 | 调度依据 |
| `binding` | `VENT-01` 或空 | 当前逻辑绑定 |

允许替换必须同时满足：通信在线、故障码为零、电机静止、能力契约匹配、机械条件允许、当前未被其他逻辑执行器占用。短电机和长电机在未完成机械及额定参数确认前，前端可用于模拟替换，但真实模式不得默认互换。

## 7. 前端大屏设计

新增独立的“硬件解耦”演示页面，延续现有深色船舶大屏风格。页面用于解释切换过程，不展开传感器设备抽象。

### 7.1 页面结构

- 顶部：当前应用、任务状态、逻辑执行器、当前绑定、恢复计时和“模拟模式/真实模式”标识。
- 左侧：稳定的软件调用链，展示“应用 → 原子服务 → 逻辑执行器”，整个替换过程中保持高亮且内容不变。
- 中部：设备抽象层和动态绑定通道，显示 `VENT-01` 当前映射到哪个设备；切换时用动画把连接线从原电机迁移到新电机。
- 右侧：三张物理电机卡片，展示名称、地址、在线/离线/异常/运行、故障码和是否兼容。
- 底部：事件时间线，按顺序展示“通信中断 → 任务保护 → 发现备用设备 → 人工确认 → 绑定更新 → 任务恢复”。

### 7.2 核心视觉信息

页面始终显示三项对比指标：

```text
应用修改：0
原子服务修改：0
设备绑定更新：1
```

动态流向分为：

- 绿色控制流：应用向下经过原子服务、逻辑执行器和设备抽象层，到达当前绑定电机；
- 青色状态流：电机状态向上返回到设备抽象层和应用页面；
- 黄色切换流：只在设备抽象层与两台物理电机之间出现，强调变化被限制在底层。

### 7.3 默认演示脚本

1. 启动“机舱通风保障”应用，`VENT-01` 绑定海风一号 `0x02`。
2. 点击模拟操作“拔出当前电机”，海风一号经过短暂检测后变为离线，任务进入保护暂停。
3. 点击“接入海岳一号”，地址 `0x0E` 变为在线待检。
4. 系统显示“发现兼容执行器”，同时保持上层应用和服务卡片不变。
5. 点击“确认切换”，绑定动画从 `0x02` 迁移到 `0x0E`。
6. 初始化检查通过，任务继续运行，页面显示恢复耗时以及“应用修改 0、服务修改 0、绑定更新 1”。
7. 可再用“注入故障”演示 `603Fh` 非零时的相同保护与切换流程。

## 8. 双模式接入边界

前端采用已经确认的双模式：

- **演示模式**：默认启用。拔出、接入、故障、发现和切换均由前端状态模型模拟，所有按钮明确标注为模拟操作，不发送真实命令。
- **真实模式**：后端状态接口可用且明确报告真实模式后启用。前端只订阅状态并提交“确认切换”意图，不拼装 Modbus 报文。

模式切换必须由后端能力握手决定，不能仅凭某个请求成功就进入真实模式。真实模式断开时，界面转为“真实连接中断”，不能自动改用模拟数据伪装设备在线。

## 9. 后端建议接口

接口名称可按现有网关规范调整，最小语义如下：

| 接口 | 作用 |
| --- | --- |
| `GET /api/executors` | 返回逻辑执行器、当前绑定和任务状态 |
| `GET /api/actuators` | 返回三台电机的在线、运行、故障和兼容性状态 |
| `GET /api/actuator-events` | 返回检测与切换事件时间线 |
| `POST /api/executors/{id}/switch-proposal` | 生成或刷新可切换设备建议 |
| `POST /api/executors/{id}/confirm-switch` | 操作员确认后执行复检、绑定和初始化 |

`confirm-switch` 请求应带目标设备、当前绑定版本和操作来源。后端使用版本校验避免两个操作同时覆盖绑定，并返回切换步骤、结果和失败原因。

## 10. 真实接入前的验证清单

1. 确认 `./test` 是否自动追加 CRC，并保存三种地址的实际响应样例。
2. 验证 `6041h` 的响应格式以及拔出后的超时表现。
3. 验证 `603Fh` 无故障和至少一种可控故障的返回值。
4. 验证 `2009h` 在静止与运行时分别返回 0 和 1。
5. 核对 `606Ch` 的读取长度、字节序和正负数表示。
6. 确认短电机与两台长电机的额定参数、转向、机械接口和允许的速度范围。
7. 确认同一 RS485 总线上不存在重复地址，且总线终端电阻和偏置正确。
8. 验证切换前的停机保护、新电机初始化和失败回滚。
9. 验证两台设备同时在线时不会把一条控制命令广播给未绑定设备。
10. 在无负载或安全测试台上完成验证后，再接入真实船舶任务。

## 11. 说明书依据与限制

参考文件：`42一体伺服_RS485型_使用手册.pdf`，IDS42-R 系列 V1.3。关键内容位于说明书印刷页 11、14、17～18、23 和 30 附近，包括 `603Fh`、`6041h`、`6061h`、`6064h`、`606Ch`、`2009h` 以及 Modbus `0x03` 读取示例。

说明书是设备协议参考，不替代现场电气与机械验证。本文给出的三组读取请求由寄存器定义推导而来，在纳入真实模式前必须用实际 `./test` 工具验证响应、CRC 行为和字节序。

## 12. 本次确认结果

- 替换策略：采用 **A，操作员一键确认切换**。
- 软件架构：应用和原子服务调用逻辑执行器，RS485 地址封装在设备抽象层。
- 状态识别：以 `6041h` 为在线心跳，结合 `603Fh` 故障码和 `2009h` 运行状态。
- 演示方式：默认前端模拟，预留后端真实接口，由能力握手切换模式。
- 安全边界：真实切换前进行兼容性、空闲、故障和初始化复检，不盲目重放旧地址的原始报文。
