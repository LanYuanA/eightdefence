# 统一船舶网关后端设计

## 1. 目标

将现有 C++ `app_gateway` 扩展为民用舰船软件定义演示的统一后端。网关负责应用定义、设备抽象绑定、任务顺序/并行调度、运行事件和控制安全状态；浏览器只负责编辑、发起操作和展示状态。

本设计覆盖任务编排、应用运行、硬件解耦、系统总图，以及安防、环境、消防页面的统一接口迁移。现有页面接口在迁移期间继续可用。

## 2. 已确认的边界

- 网关使用 C++17 和现有 `application/web_server.cpp`，不新增 Node.js 运行依赖。
- 应用定义和逻辑执行器绑定采用本地 JSON 持久化；运行事件采用 JSON Lines 追加日志。
- 任务引擎是运行状态的唯一来源。浏览器刷新、切换页面或关闭后，不改变网关内任务状态。
- 一个网关可以同时运行多个应用实例。每个实例独立保存步骤索引、节点状态、进度、传感器快照和事件。
- 态势感知服务优先使用现有设备轮询数据；传感器不可用时返回明确标记为 `demo` 的演示快照。
- 执行服务通过适配器调用。第一阶段总执行器开关默认关闭，因此任务只产生 `simulated` 结果，绝不写入串口。
- 未来真实控制采用本地人工解锁：控制默认锁定，解锁有效 10 分钟，所有解锁和控制请求写入审计事件。即使解锁，未注册或未启用的执行器仍不得下发。
- 旧 `/security/api/...`、`/environment/api/...`、`/fire/api/...` 和现有网关 `/api/...` 接口保留；新功能统一使用 `/api/v1/...`。

## 3. 模块结构

```text
application/marine/
  json_value.*            最小 JSON 读写、输入校验和转义
  marine_types.*          应用、步骤、节点、运行、事件、绑定的数据结构
  marine_repository.*     apps.json 与 bindings.json 的原子读写
  marine_executor.*       态势读取、模拟执行与未来真实执行器适配边界
  marine_runtime.*        多任务顺序/并行调度、暂停、继续、停止和恢复规则
  marine_safety.*         控制总开关、10 分钟解锁和审计事件
  marine_api.*            `/api/v1` 请求解析与 JSON 响应
```

`web_server.cpp` 仅保留 HTTP 读取、静态文件服务和路由分发；它将 `/api/v1/marine/...` 请求交给 `MarineApi`。串口对象、已轮询的设备对象和命令队列只通过 `MarineExecutor` 注入，业务层不直接拼接 Modbus 帧。

## 4. 持久化与恢复

网关在工作目录 `data/marine/` 维护下列文件：

| 文件 | 内容 | 写入规则 |
| --- | --- | --- |
| `apps.json` | 应用定义数组 | 写入临时文件后 `rename` 原子替换 |
| `bindings.json` | 逻辑执行器到物理设备的绑定 | 写入临时文件后 `rename` 原子替换 |
| `events.jsonl` | 解锁、控制、任务状态和绑定事件 | 每行一个完整 JSON 对象，追加写入 |
| `runs.json` | 当前和已结束任务的摘要 | 每次状态转换原子替换 |

应用创建、更新和删除都先校验：名称非空、至少一个步骤、步骤非空、服务已实现、参数范围有效、同一步骤不存在资源冲突。网关启动时读取四类文件；任何运行中实例恢复为 `interrupted`，并记录“网关重启，需人工重新启动”。

## 5. 任务与服务模型

应用由有序 `steps` 组成。每个步骤包含一个或多个节点；步骤内节点并行运行，只有全部完成才进入下一步骤。运行状态为：`idle`、`running`、`paused`、`completed`、`cancelled`、`failed`、`interrupted`。节点状态为：`waiting`、`running`、`completed`、`cancelled`、`failed`。

调度器在网关后台以 100 ms 节拍运行。每次调度读取统一传感器快照，使用节点持续时间计算进度，并写入事件。态势服务从快照生成结果；执行服务请求 `MarineExecutor`。当执行器总开关关闭时，执行器返回与现有前端一致的模拟结果和 `source: "simulated"`。异常会停止当前实例中尚未完成的节点，不影响其他应用实例。

逻辑执行器以稳定 ID（例如 `VENT-01`）表示，绑定记录包含 `logicalExecutorId`、`deviceId`、`bus`、`address`、`capabilities`、`version` 和更新时间。应用与原子服务不得保存 RS485 地址。设备切换需要候选设备在线、无故障、能力匹配且绑定版本一致；第一阶段只保存和展示绑定状态，不执行真实初始化或控制。

## 6. 安全控制

`MarineSafety` 同时满足三个条件才允许真实控制：全局 `actuatorControlEnabled` 为真、解锁尚未过期、目标执行器在设备注册表中显式标为 `realControlEnabled`。初始配置中三个条件均不满足。

`POST /api/v1/safety/unlock` 接收 `operator`，生成持续 600 秒的本地会话；`POST /api/v1/safety/lock` 立即锁定。每个状态改变、每次被拒绝的控制和每次允许的控制都写入 `events.jsonl`。接口不实现网络用户认证；该模式只适用于本机离线演示，生产部署需在该边界外增加身份认证和网络访问控制。

## 7. 新接口

所有响应使用 `application/json; charset=utf-8`，错误结构固定为：

```json
{"error":{"code":"validation_failed","message":"步骤 1 还没有服务。"}}
```

| 方法和地址 | 请求/响应 | 行为 |
| --- | --- | --- |
| `GET /api/v1/health` | 返回版本、存储状态、传感器模式和控制锁定状态 | 网关健康检查 |
| `GET /api/v1/marine/apps` | 返回应用定义 | 读取已持久化应用 |
| `POST /api/v1/marine/apps` | 应用定义 | 校验后创建，返回 201 |
| `GET /api/v1/marine/apps/{id}` | 返回单个应用 | 不存在返回 404 |
| `PUT /api/v1/marine/apps/{id}` | 完整应用定义 | 校验后更新 |
| `DELETE /api/v1/marine/apps/{id}` | 返回 204 | 存在运行实例时返回 409 |
| `POST /api/v1/marine/runs` | `{ "appId": "..." }` | 创建并启动一个独立运行实例 |
| `GET /api/v1/marine/runs` | 返回全部运行摘要 | 支持多应用并行展示 |
| `GET /api/v1/marine/runs/{id}` | 返回运行、节点和事件 | 前端轮询主接口 |
| `POST /api/v1/marine/runs/{id}/pause` | 返回最新状态 | 只允许 `running` 实例 |
| `POST /api/v1/marine/runs/{id}/resume` | 返回最新状态 | 只允许 `paused` 实例 |
| `POST /api/v1/marine/runs/{id}/cancel` | 返回最新状态 | 取消未完成节点 |
| `GET /api/v1/marine/executors` | 返回逻辑执行器和绑定 | 硬件解耦与总图数据源 |
| `PUT /api/v1/marine/executors/{id}/binding` | `{ "deviceId":"MOTOR-0E", "expectedVersion":3, "operator":"演示员" }` | 校验版本与能力后更新绑定 |
| `GET /api/v1/safety` | 返回控制状态和剩余秒数 | 页面展示安全锁 |
| `POST /api/v1/safety/unlock` | `{ "operator":"演示员" }` | 本地解锁 600 秒 |
| `POST /api/v1/safety/lock` | `{ "operator":"演示员" }` | 立即恢复锁定 |

## 8. 迁移与兼容

第一批前端迁移只替换 `MarineDemo.vue` 和 `HardwareDecoupling.vue` 的应用、运行、事件、绑定、传感器和安全状态来源。若 `/api/v1/health` 不可访问，页面继续进入现有纯前端演示模式，并显示“本地演示数据”，确保离线静态交付包可用。

安防、环境、消防页面随后按资源读取、状态读取、控制请求和日志读取四类接口迁移到 `/api/v1`。原接口在至少一个完整演示版本内保留为适配层，响应字段不变；迁移期间不删除旧路由。

## 9. 验收场景

1. 创建包含串行和并行步骤的应用，重启网关后应用仍能读取。
2. 同时启动两个应用，暂停、取消或失败其中一个不改变另一个的状态。
3. 浏览器刷新后重新请求运行实例，看到同一任务进度和事件。
4. 网关在任务运行时重启，任务显示 `interrupted`，不能自动继续。
5. 传感器在线时态势服务结果使用真实数值；传感器离线时结果标为 `demo`。
6. 控制总开关关闭时，执行任务不写入命令队列，结果标为 `simulated`。
7. 解锁超过 600 秒或主动锁定后，真实控制请求被拒绝并记录事件。
8. 使用过期的绑定版本更新执行器，返回 409，原绑定不改变。
9. 旧 `/api/data`、`/environment/api/...`、`/security/api/...` 与 `/fire/api/...` 请求继续返回原格式响应。
10. 在奇安信浏览器中运行“任务编排 → 一键演示 → 双应用并行 → 数据流图 → 硬件绑定切换”全流程，页面显示由 `/api/v1` 返回的状态。

## 10. 风险与非目标

- 真实执行器尚未完成单机验证，因此本设计不启用任何 RS485 电机、泵或风机控制命令。
- JSON 持久化满足单机离线演示，不提供多网关复制、复杂查询或强事务；需要集中运维时再迁移 SQLite。
- 现有 HTTP 服务器是轻量实现，本阶段不增加互联网暴露、远程用户管理或 TLS。
- 旧页面迁移按接口分类逐步完成，不与任务引擎基础模块在同一提交中大规模重写。
