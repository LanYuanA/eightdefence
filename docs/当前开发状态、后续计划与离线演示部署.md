# 船舶软件定义演示项目开发状态、后续计划与离线部署

更新日期：2026-09-08

## 1. 项目目标

本阶段将原有设备监测前端改造成面向会议大屏的软件定义民用船舶演示平台，重点说明两项能力：

1. **软软解耦**：原子服务只实现一次，可根据任务订单通过顺序和并行编排生成多个独立应用。
2. **软硬解耦**：应用和原子服务面向逻辑执行器，RS485 地址、协议和具体电机差异由设备抽象层吸收。

当前演示默认使用软件模拟。态势感知服务可以读取现有传感器接口；接口不可用时自动标明并使用演示数据。硬件替换操作只改变前端演示状态，不发送电机指令。

## 2. 当前已经完成的工作

### 2.1 页面结构与视觉

- 默认首页改为“任务编排”，并保留服务目录、应用运行、硬件解耦和原系统总图入口。
- 适配 1920×1080 会议大屏，并检查 1100 像素宽窗口。
- 首屏增加“选择任务、组合服务、生成应用、并行运行”四步说明。
- 增加价值指标：新增开发、跨应用复用、已生成应用、正在运行应用。
- 任务订单 A/B 直接对比服务组合，高亮复用的 02 冷却循环和 03 供水增压。
- 增加一键演示和应用生成动画。

### 2.2 原子服务和任务编排

- 共展示 21 项船舶业务服务。
- 7 项态势感知服务已接入现有 12 路传感器数据定义。
- 4 项执行控制服务已经实现软件模拟：舱室通风、冷却循环、供水增压、舱底排水。
- 其余 10 项作为扩展能力展示，并明确标记为待实现。
- 支持拖拽添加服务、调整步骤、顺序执行和步骤内并行执行。
- 支持区域、强度、持续时间和采样窗口参数。
- 支持资源冲突校验，例如供水与排水共用水务资源时不能在同一步骤并行。

### 2.3 应用生成与多应用运行

- 每次生成都会在软件基座中增加一个独立、可点击的应用页面。
- 每个应用拥有独立的运行器、进度、事件、暂停、停止和故障状态。
- 多个应用可以同时运行，切换页面只改变当前查看对象。
- 一键演示自动生成并同时启动：
  - APP 01：开航辅助保障，执行服务为 01 + 02 + 03。
  - APP 02：作业后恢复保障，执行服务为 02 + 03 + 04。
- 两个应用直接复用 02 和 03，无需增加新的服务实现。

### 2.4 每个应用自动生成数据流图

数据流图由应用编排自动推导，不使用写死的节点。切换应用后，传感器、原子服务、设备抽象和硬件节点会同步变化。

- 态势数据路径：`具体传感器 → 态势感知原子服务 → 当前应用`。
- 控制路径：`当前应用 → 执行控制原子服务 → 设备抽象层 → 执行器硬件`。
- 传感器不做设备抽象，设备抽象层只处理执行器差异。
- 底层将态势感知资源和执行器硬件放在同一物理资源层。
- 蓝色动态光点表示态势数据向上流动，绿色动态光点表示控制指令向下流动。
- 图中同步显示传感器数值、在线状态、服务步骤以及等待、运行、完成和异常状态。

### 2.5 软硬解耦演示

- 增加独立硬件解耦页面，演示逻辑执行器与三台不同 RS485 地址电机之间的动态绑定。
- 支持模拟拔出、离线、故障、发现候选设备、人工确认切换和恢复运行。
- 页面突出显示应用修改 0、原子服务修改 0、设备绑定更新 1。
- 采用方案 A：运行时维护逻辑执行器到物理设备地址的绑定，应用和原子服务不保存 Modbus 地址。
- 已记录电机说明书中的状态字、故障码、电机状态和转速读取方案。

### 2.6 主系统数据流图

- 原主界面改为四层软件定义结构：应用层、原子服务层、设备抽象层、物理资源层。
- 物理资源层同时展示态势感知和执行器硬件。
- 新生成应用会进入主系统应用层。
- 动态光点分别展示态势数据上行和控制指令下行。

## 3. 当前技术结构

| 位置 | 作用 |
| --- | --- |
| `ui/src/marine/model.ts` | 服务目录、任务模型、示例应用、校验规则 |
| `ui/src/marine/sensors.ts` | 12 路传感器与 7 项态势感知服务的映射 |
| `ui/src/marine/runner.ts` | 顺序/并行调度和执行软件模拟 |
| `ui/src/marine/application-flow.ts` | 根据应用编排自动生成数据流模型 |
| `ui/src/marine/actuators.ts` | 硬件替换演示状态机 |
| `ui/src/views/MarineDemo.vue` | 编排、软件基座和多应用运行页面 |
| `ui/src/components/marine/ApplicationFlow.vue` | 每个应用的数据与控制流线图 |
| `ui/src/views/HardwareDecoupling.vue` | 软硬解耦独立演示页面 |
| `ui/src/components/SoftwareDefinedFlow.vue` | 原主界面的全局软件定义数据流图 |
| `public/`、`dashboard.html` | C++ 网关实际托管的构建产物 |

构建目标设置为 Chrome 83，降低国产 Chromium 内核浏览器的兼容风险。前端构建产物不依赖外部 CDN、在线字体或互联网接口。

## 4. 当前限制

- 01 至 04 执行服务仍是浏览器软件模拟，不控制真实电机、泵或风机。
- 硬件解耦页面尚未连接真实串口状态和切换接口。
- 已生成应用保存在当前浏览器的 `localStorage`，不会在不同机器之间同步。
- 应用运行状态位于浏览器内存，刷新页面后不会继续运行。
- 真实传感器依赖 `/api/data`。纯静态离线演示没有网关时会自动使用演示数据，并显示“演示数据”。
- 当前前端主包约 1.5 MB，功能正常，但后续可通过按页面拆包缩短首次加载时间。
- 已使用奇安信可信浏览器国密开发者专版 `1.0.46401.7`（ARM64）完成实测；目标机仍建议在正式演示前按现场版本再做一次试运行。

## 5. 后续开发计划

- 在目标麒麟机器确认 CPU 架构、奇安信浏览器版本、屏幕分辨率和 Python 3 是否可用。

### P1：真实执行器接入

- 电机单机测试通过后，将状态查询、转速 RPM、故障码和控制接口放到后端。

- 前端只展示状态并提交操作意图，不在浏览器中直接发送串口指令。
- 验证 0x02、0x0E、0x0F 三个地址设备在不修改应用和服务的情况下完成替换。

### P2：服务端任务引擎

- 将当前浏览器运行器迁移到后端，支持掉电恢复、长期运行和多客户端查看。
- 保存应用版本、任务实例、参数快照、执行事件和失败原因。

### P3：扩展原子服务

### P4：工程化和交付

- 增加角色权限、操作确认、日志归档和演示数据重置。

- 增加奇安信浏览器和目标麒麟版本的固定验收清单。

## 6. 麒麟系统离线演示方案

### 6.1 推荐方案：纯前端离线包 + Python 本地服务器

此方案不启动设备轮询，不访问真实串口，最适合给领导演示界面。

开发机准备：

```bash
cd /home/kylin/ylz/work/eightdefence
make frontend
mkdir -p 船舶软件定义离线演示/web
cp -R ui/dist/. 船舶软件定义离线演示/web/
tar -czf 船舶软件定义离线演示-20260908.tar.gz 船舶软件定义离线演示
sha256sum 船舶软件定义离线演示-20260908.tar.gz > 船舶软件定义离线演示-20260908.sha256
```

将以下资源通过经过允许的 U 盘或移动介质带到目标机：

1. `船舶软件定义离线演示-20260908.tar.gz`。
2. 对应的 `.sha256` 校验文件。
3. 本文档或一份打印版启动说明。
4. 如果目标机没有 Python 3，还需要提前准备与目标麒麟版本及 CPU 架构匹配的本地 HTTP 服务器程序或 Python 3 离线安装包。
5. 建议额外携带 1920×1080 的演示截图或录屏，作为浏览器异常时的兜底材料。

目标机启动：

```bash
sha256sum -c 船舶软件定义离线演示-20260908.sha256
tar -xzf 船舶软件定义离线演示-20260908.tar.gz
cd 船舶软件定义离线演示/web
python3 -m http.server 8080 --bind 127.0.0.1
```

然后在奇安信浏览器输入：

```text
http://127.0.0.1:8080/
```

必须从根地址进入，再使用页面内按钮切换“硬件解耦”和“系统总图”。Python 简单服务器没有 Vue 路由回退功能，因此不要在子页面刷新，也不要直接输入 `/hardware-decoupling`。

结束演示后回到终端按 `Ctrl+C` 停止本地服务器。

### 6.2 备选方案：携带 C++ 网关和 public 目录

需要同时演示真实传感器时，可以携带：

- `app_gateway`
- `public/`
- `dashboard.html`
- 与目标机匹配的运行库和设备配置

当前 `app_gateway` 是 ARM64 动态链接程序，目标机必须同为 ARM64，并具备兼容的 `glibc`、`libstdc++`、`libgcc` 和 `libpthread`。该程序会初始化串口和设备轮询，因此现场仅展示前端时不建议使用此方案。使用前还要确认串口权限、设备路径和 8080 端口占用情况。

### 6.3 奇安信浏览器现场检查

在正式演示前至少检查以下项目：

1. 浏览器可以打开 `http://127.0.0.1:8080/`，控制台没有脚本语法错误。本项目已使用麒麟 V10 自带 Chromium 83.0.4103.61，以及奇安信可信浏览器 1.0.46401.7，验证最终离线构建可以正常显示。
2. 分辨率设为 1920×1080，浏览器缩放为 100%，进入全屏后标题和按钮没有被裁切。
3. 点击“一键演示”能够出现生成动画，并进入包含两个应用页面的软件基座。
4. 顶部显示“2 个应用、2 个正在运行”。
5. 切换 APP 01 和 APP 02 后，数据流图节点会自动变化。
6. 硬件解耦页面可以完成拔出、候选接入、人工确认和恢复动画。
7. 断开所有网络后重复以上操作，确认没有外部资源依赖。
8. 如果动画卡顿，关闭浏览器节能模式和其他大页面，并确认硬件加速可用；不要临时升级浏览器。

### 6.4 不推荐的打开方式

- 不要直接双击 `index.html`。当前资源使用根路径，ES 模块和浏览器安全策略也可能阻止 `file://` 正常运行。
- 不要在目标机临时执行 `npm install`。所有依赖已经编译进 `ui/dist`，离线机器不需要 Node.js 或 npm。
- 不要复制整个 86 MB 的历史 `public` 目录作为纯前端包。`ui/dist` 只有当前有效版本，体积约 2.1 MB，内容更明确。
