# 船舶软件组合演示

## 本阶段范围

会议大屏演示“软软解耦”：共展示 21 项业务服务。A01 至 A07 为态势感知服务，覆盖现有温度、湿度、PM2.5、PM10、TVOC、甲醛、CO₂、烟雾、水浸、红外、雷达和光照共 12 路数据；01 至 04 为执行控制服务，已经实现软件模拟；其他 10 项明确标记为待实现。

首页直接进入船舶演示。传感器按业务粒度封装成可编排的态势感知服务。网关在线时，感知服务读取 `/api/data` 的真实数据；网关不可用时自动使用带有明确标识的演示数据。原设备管理与监测页面保留在“原系统入口”，其软件定义数据流图按四层结构展示：最上方为应用层，其下依次为原子服务层、设备抽象层，最下方为处于同一层的态势感知与执行器硬件。

这是软件模拟，不向电机发送命令。应用保存在当前浏览器，未保存的更改在切换任务时会提醒；不同电脑或浏览器之间不自动同步。

## 演示步骤（约 3 分钟）

1. 打开首页，点击右上角“全屏演示”。建议使用 1920 × 1080 或更高分辨率。
2. 指向首屏四步路径“选择任务 → 组合服务 → 生成应用 → 并行运行”，说明任务订单只定义服务组合关系。下方 A/B 对比中，02 冷却和 03 供水保持同色，代表同一服务被两个应用直接复用。
3. 点击“一键演示”。生成动画会同时显示：新增服务开发 0、共享原子服务 2、新应用页面 2、可并行运行 2。
4. 动画结束后自动进入软件基座。指出 APP 01“开航辅助保障”和 APP 02“作业后恢复保障”是两个独立、可点击的页面，顶部显示“2 个应用、2 个正在运行”。切换页面只改变当前查看对象，两个应用仍同时推进。
5. 在运行页面观察每个应用自动生成的“数据与控制流线图”。蓝色光点表示具体传感器数据经态势感知服务汇入应用，绿色光点表示应用指令经执行原子服务和设备抽象层到达硬件。切换 APP 01 与 APP 02，图中的传感器、原子服务、设备抽象和执行器会按各自编排自动变化。
6. 返回“任务编排”，点击订单 A：先并行读取温湿度、颗粒物和气体态势，再执行 01 通风，最后并行执行 02 冷却与 03 供水。顶部“生成应用”和“运行”按钮在首屏内可直接操作。
7. 点击订单 B：先读取 A05 水浸态势，并行执行 02、03，最后执行 04 排水。说明改变任务只需要重新排列现有服务，不需要开发新的业务软件。
8. 点击订单 C“全船安全巡检”：它只组合 7 项态势感知服务，不依赖电机，覆盖现有全部传感器数据。
9. 点击“新建应用”，输入任务名称和目标。从服务库拖入感知或执行服务组成顺序步骤；将多个服务放进同一步骤就形成并行组。点击卡片设置区域、采样窗口、强度和时长。
10. 点击“生成应用”。生成动画结束后，软件基座增加一个独立应用页面；该应用也会同步进入原主界面的应用层。
11. 在“服务目录”说明：每张卡片代表完整业务能力，感知服务读取现有传感器数据，执行服务接收统一的区域、强度和时长参数。“模拟服务异常”只影响当前应用实例及其后续步骤，不会停止其他应用。
12. 点击“系统总图”进入原主界面。刚保存的应用会以绿色 `NEW` 卡片进入应用层；左侧动态光点表示态势数据向上流动，右侧动态光点表示控制指令向下流动。

## 交互说明

- 拖动步骤空白区域或使用步骤右上角左右箭头，可调整步骤顺序。
- 拖动服务卡片到其他步骤可改变分组，拖到“新步骤”可拆出顺序步骤。
- 不便拖拽时，点击步骤标题选中步骤，再点服务库的“＋”添加；参数面板也可选择移动到哪个步骤。
- 并行组会等待所有服务完成。不同持续时间的服务独立完成，不会提前启动后续步骤。
- 03 供水与 04 排水暂共用“水务执行器”，同一步骤内冲突时会提示拆成顺序步骤；这是当前软件模型的资源映射，待电机测试后可调整。
- 感知服务按运行开始时的数据快照计算结果，不把传感器画成可控制设备。真实接口可达但某项设备离线时，该服务会明确显示“设备离线”，不会偷偷替换为演示值。
- 每个应用的数据流图由编排自动生成。传感器只作为态势数据来源，不进入设备抽象；设备抽象层只吸收执行器的地址、协议和型号差异。
- 强度影响冷却流量、供水压力和排水量；时长决定运行进度。通风结果表示本轮换气任务进度，排水完成表示本轮定时排水结束，不代表实际舱底已经排空。
- 每个应用使用独立运行器和启动时的任务快照，可以同时运行。正在运行的应用会锁定自身编排；其他应用仍可查看和启动。离开页面或刷新不会在后台继续控制设备。

## 硬件解耦演示（方案 A，约 2 分钟）

1. 从软件组合页顶部点击“硬件解耦”，或直接打开 `/hardware-decoupling`。页面初始展示“机舱通风保障”应用通过“舱室智能通风”原子服务调用逻辑执行器 `VENT-01`，当前绑定海风一号 `0x02`。
2. 指出右上方核心指标：应用修改 0、原子服务修改 0、设备绑定更新 0。三台电机地址不同，但地址没有进入应用和原子服务。
3. 点击“拔出当前电机”。海风一号变为离线，任务进入保护暂停；左侧应用和原子服务仍保持不变。
4. 在海岳一号 `0x0E` 卡片点击“模拟接入”。系统识别它为兼容执行器并进入“等待人工确认”，不会未经确认直接驱动新设备。
5. 点击“操作员确认切换”。中央动态绑定从 `0x02` 迁移到 `0x0E`，完成初始化动画后任务恢复运行。
6. 指出最终指标变为“应用修改 0、原子服务修改 0、设备绑定更新 1”。这说明物理地址和硬件差异被设备抽象层吸收。
7. 点击“重置场景”，再使用“注入运行异常”演示故障码触发的相同保护与替换流程。

当前页面运行演示模式，所有拔出、接入、异常和替换操作只改变前端状态，不发送串口命令。后续真实模式由后端轮询 `6041h` 状态字、`603Fh` 故障码和 `2009h` 电机状态，前端只展示状态并提交操作员的切换确认。

## 本地运行与交付

开发预览：在 `ui` 目录运行 `npm run dev -- --host 0.0.0.0`，使用终端显示的地址。

编译并更新现有 C++ 网关托管的前端：项目根目录运行 `make frontend`。它会将完整前端产物复制到 `public`，并同步 `dashboard.html`。无需修改或重新编译电机与传感器代码。

软件调度检查：在 `ui` 目录运行 `npm run test:marine`（Node.js 22.6+）；完整前端检查运行 `npm run build`。

## 后续设备接入位置

- `ui/src/marine/model.ts`：服务目录、统一任务参数、资源约束和三套示例应用。
- `ui/src/marine/sensors.ts`：12 路现有传感器数据与 7 项态势感知服务之间的映射。
- `ui/src/marine/runner.ts`：感知数据快照、四项执行模拟及顺序/并行调度，目前在浏览器执行。
- `ui/src/marine/application-flow.ts`：根据应用编排自动推导传感器、原子服务、设备抽象和执行器硬件节点。
- `ui/src/components/marine/ApplicationFlow.vue`：每个应用独立的数据与控制流线图及运行状态动画。
- 电机就绪后，应在后端实现执行器适配及任务调度，通过接口向前端报告状态。不能把当前浏览器计时器直接用于真实设备控制。
- `ui/src/marine/actuators.ts`：软硬解耦演示状态机，封装离线、故障、候选发现、人工确认、绑定更新和恢复过程。
- `ui/src/views/HardwareDecoupling.vue`：独立的执行器替换大屏，默认只运行前端模拟；电机测试完成后按设计文档接入后端真实状态接口。
